GTO 翻後解算器 — 使用說明

【Windows 最快用法】
  雙擊 start.bat → 瀏覽器會開啟「六人桌」介面：
    1. 在牌桌上點兩個座位（先行動者自動當開池者），選 SRP / 3-bet / 4-bet 底池
    2. 點選 3–5 張牌面（或按「隨機翻牌」），進階設定可調籌碼、下注尺度、迭代次數
    3. 按「開始解算」，完成後下方直接顯示結果（牌桌上會標出目前行動者與每條街的動作）
  使用期間請保持 start.bat 開出的黑色視窗開著；關掉視窗即停止。
  介面上的設定會寫回 config.txt，所以也可以照下面的方式用指令列執行。
  solver.exe 已編譯好，任何 64 位元 Windows + x86 CPU 都能執行。
  若某台電腦跑不起來，雙擊 check.bat，它會檢查環境並產生 check_result.txt，看裡面哪一項是 [FAIL]。

【預解算資料庫（可放在其他電腦一直跑）】
  1. 把整個資料夾複製到要跑的電腦（只需要 solver.exe、ranges_6max.txt、presolve.txt、presolve.ps1、presolve.bat）
  2. 雙擊 presolve.bat 就會開始，依 presolve.txt 的順序把每個對決情境的 1755 種翻牌全部解完
     （1755 = 花色同構後不重複的翻牌數，任何翻牌都能對應到其中一個）
     - 隨時可以關閉視窗，下次打開會從中斷處繼續，已算好的會跳過
     - 執行期間電腦不會進入睡眠；解算程式以較低優先權執行，不影響電腦其他工作
     - 視窗標題會顯示進度與預估剩餘時間
  3. 結果在 library\<對決>_<底池類型>\<翻牌>.js；把 library 資料夾複製到你自己的電腦
     （放在 start.bat 同一層），在六人桌介面選好座位、底池類型和翻牌，
     若資料庫已收錄就會出現「立即載入」，不用等待
  預設存到轉牌（gzip 壓縮），河牌在介面瀏覽時即時解算（約 1 秒），不需預存。
  參考（Ryzen 9 5900X / DDR4-2666）：每個翻牌約 1 分鐘、壓縮後約 5MB；一個情境約 30 小時、9GB。
  presolve.txt 的 parallel_jobs 控制同時跑幾個解算（預設自動），實測比單一解算用滿所有核心更快。
  要調整情境順序、下注尺度、精確度，請編輯 presolve.txt（改了解算參數建議換一個 library 資料夾名稱）。

【翻前範圍編輯（例如照 GTO Wizard 調整）】
  用 start.bat 開啟，選好兩個座位與底池類型後，下方「翻前範圍」會列出這個對決雙方實際使用的範圍。
  可以用筆刷照圖點格子，或把範圍文字貼進文字框（AA,AKs:0.5 或 AKs: 72.5 這種百分比都可以），按「儲存範圍」。
  開池範圍存成 rfi_位置；其他存成只針對這個對決的項目（例如 call_BB_vs_BTN），不影響別的對決。
  第一次儲存時會備份原始檔為 ranges_6max.original.txt。

【即時解算下一條街】
  用 start.bat 開啟時，瀏覽結果走到「此街未輸出」的發牌節點（例如轉牌結束要發河牌），
  直接點一張牌，就會用當下雙方剩餘範圍、底池、籌碼即時解出後續策略；「上一步」可退回原本的結果。

【編譯】（每台電腦只需做一次，把整個資料夾複製過去即可）
  macOS / Linux：在終端機執行  ./build.sh        （需要 Xcode Command Line Tools 或 g++/clang++）
  Windows：      雙擊或執行    build.bat         （需要 Visual Studio 的 C++ 工具，或 MinGW-w64 的 g++）

【執行】
  macOS / Linux：./solver config.txt
  Windows：      solver.exe config.txt

【看結果】
  用瀏覽器開啟 viewer.html（需與 result.js 放在同一個資料夾）。

【設定】
  所有可調項目都在 config.txt，內有註解。
  程式開始時會印出預估記憶體用量；若超過電腦記憶體，請減少下注尺度、縮小範圍或降低 raise_cap。
  isomorphism（花色同構）只在雙方範圍對該兩個花色完全對稱時才會生效；
  若範圍裡指定了單一花色組合（例如 AhKh），相關花色就不會合併，結果仍然正確，只是較慢。

【六人桌對決】
  在 config.txt 設定 matchup（例如 CO vs BTN）與 pot_type（srp / 3bp / 4bp），
  程式會從 ranges_6max.txt 帶入雙方範圍，並算出底池、剩餘籌碼與誰先行動。
  ranges_6max.txt 內是近似的翻前範圍，可換成你自己的。
  注意：翻後解算固定為兩人對決；三人以上同時在底池的多人底池不支援。
